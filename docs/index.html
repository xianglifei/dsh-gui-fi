FI · MACOS / v1.0.0

dsh 还是那个 dsh，
只是住进了
原生窗口。

fi 是一个 Electron 外壳：spawn 你本机装的 dsh，把 Web 界面装进一个真正的 macOS 窗口。页面一行没改，独立 profile 不碰浏览器里的登录，dsh 出新版当天可用。

01它解决什么

浏览器里那套工作流，
缺的从来不是功能。

dsh 的 Web 界面已经够用。缺的是一个能一直开着、能被 Finder 叫出来、关掉也不打断任务的入口。

BEFORE以前
  • 任务混在十几个浏览器标签页里，关掉就断
  • 换项目＝cd 到目录，再回浏览器挑工作区
  • 拖进对话的文件变成一份上传副本
  • 退出前只能凭眼睛猜有没有任务在跑
AFTER现在
  • Dock 上一个窗口，关窗只是隐藏
  • 侧栏里逐层翻文件夹，行尾加号直接开任务
  • 文件按 @path 引用，留在原地
  • 退出前查 session/list，2 秒超时按有任务算
02它怎么工作

一条握手行，
撑起整个窗口。

fi 只依赖 dsh 的一条最小契约：spawn 之后，stdout 里那行带 token 的登录 URL。其余都是壳自己的事。

STEP 01

起 dsh

--profile fi --port 0 --no-open：独立 profile，随机回环端口，不打开浏览器。

STEP 02

读握手

从 stdout 解析 dsh web: http://127.0.0.1:<port>/?token=…，30 秒等不到就报错。

STEP 03

装进窗口

loadURL 换 30 天 HttpOnly cookie，落在 persist:fi 分区；页面就是浏览器里的 dsh。

STEP 04

守生命周期

崩溃指数退避重启（上限 30 秒）；退出 SIGTERM → SIGKILL 回收；单实例，二次启动只唤回窗口。

dsh 的 bin 由 fi 自带的 Electron 以 Node 模式执行（ELECTRON_RUN_AS_NODE + --expose-internals，官方 Desktop host 同款机制）——运行 dsh 不再要求系统 PATH 上有 Node。

03一个架构决定

不把 dsh 打进去，
才跟得上 dsh。

官方 Desktop 把整个运行时打进 app，版本与 dsh 锁死——升 dsh 必发新版。fi 走相反的路：spawn 你装的那份 dsh，只认 stdout 那一行 URL 和 /api 表面。

  • 升级跟着 dsh 走。dsh 出新版，装完重启窗口即可，不用等壳发版。
  • 页面零差异。没有自定义 scheme、没有反向代理；浏览器里 dsh 怎么显示，窗口里就怎么显示。
  • 同一个插件体系。侧栏主体走 dsh 的 slot 与客户端模块，不是重写页面。
  • 代价写在明处。机器上得先装 dsh；握手行格式若变，要同步 URL_LINE_RE。

04项目模式

侧栏里，
先看见文件夹。

项目模式把侧栏换成 Finder 式的逐层浏览器：面包屑就是路径条，文件夹行尾的加号在那一层直接开一个新任务。

  • 逐层进入，不做树。层级栈既是导航也是路径条；点面包屑跳转，返回上一级，手动刷新。
  • 文件交给系统。单击用默认程序打开；右键复制路径、在 Finder 中显示、打开。
  • 隐藏项可选。点前缀条目默认不展示，眼睛按钮切换，选择记在 localStorage 里跨重启。
  • 单层上限 1000 条。超出显示 truncated；符号链接按目标归类，断链灰显不可点。

05关窗与退出

关窗不是退出，
是把它收进 Dock。

macOS 上点关闭只是隐藏：会话、草稿和定时任务继续跑。真正退出时才问一句——而且问得有依据。

  • 怎么找回。Dock 图标、再次启动、fi:// 深链，三条路都回到原来的窗口，滚动位置还在。
  • 怎么判忙。主信号是 dsh /api 的 session/list：running 字段覆盖全部工作区，含定时任务派发的会话；查询超时 2 秒，按有任务处理。
  • 失配就降级。API 不可用时退回停止按钮的文案嗅探（中英文），再失配就静默放行，不挡人。
  • 彻底退出。⌘Q 或菜单「退出」；Windows / Linux 仍是关窗即退出。

还有 3 个任务在进行中

去查了 session/list 的 running，覆盖全部工作区与后台任务。退出会中断它们。

06还有一些

主卖点之外，
还有几件顺手的事。

它们都不是壳的全部理由，但都是每天会碰到的动作。

CRON

定时任务

每 N 分钟 / 每天 / 每周 / 每月，指定工作区或项目文件夹、次数上限。30 秒轮询，任务落盘 fi-cron-tasks.json。

PLUGINS

插件中心

只管 fi 自己的 profile：已安装可卸载（两步确认），推荐位用 github:owner/repo 直装，不经 npm registry。

QUOTE

选区引用

对话里选中一段文字挂成引用 chip，发送时并入提示词。单条 8000 字、最多 8 条、总量 16000 字。

FINDER

Finder「在 fi 中打开」

任意文件夹右键「服务 → 在 fi 中打开」，带路径深链直达并开新任务。先弹系统确认，取消是默认。

⌘K

搜索标题与全文

⌘K 打开居中搜索：标题本地匹配 + 消息内容全文检索（SQLite FTS，上限 20 条），250ms 防抖，覆盖全部工作区。

07界面与取舍

看起来像 dsh，
用的是 dsh 的槽位。

fi 不自带一套设计语言：颜色、间距、深浅主题全跟着 dsh。它只在 dsh 给的槽位上，长出 fi 自己的部件。

01

侧栏是插件，不是补丁

客户端模块以 priority: -1 影子接管 sidebar.workspaces 槽位。dsh 大版本改内部契约时，它静默退回原生侧栏——功能可能少一块，但界面不会坏。

02

线稿图标，刻意区分

fi 自有 UI 全量用 Lucide 线稿（24 网格 stroke），与 dsh 自身的 fill 图标区分开；未收录的名字回落 dsh primitives，新调用点永远可用。

03

原生文件桥，被动探测

只有探测到官方桌面桥面才点亮：__DSH_HOST_PATHS__ 让拖入文件变成 @path，__DSH_DIRECTORY_PICKER__ 走系统目录对话框。

04

不伪造桌面标记

刻意不设 <html data-platform>：dsh 的 ShortcutsService 会据此进桌面分支、强制要求 window.dshDesktop.keyboard 桥，缺桥直接抛错。

窗口 1280 × 800 · 最小 900 × 600 窗口标题品牌为「fi」 主题、字号、间距全部继承 dsh
08安装

源码装，
三分钟。

fi 目前以源码方式安装，打 dmg 在路线图上。前置：macOS、Node ≥ 20、pnpm、dsh CLI。

1

装 dsh CLI

fi 不内置 dsh，跑的是你 PATH 上的这一份。

npm install -g @deepseek-ai/dsh
2

拿代码、装依赖

需要 Node.js ≥ 20 与 pnpm。

git clone https://github.com/xianglifei/dsh-gui-fi.gitcd dsh-gui-fi && pnpm install
3

启动

构建并启动；开发时用 pnpm dev。首次启动会初始化独立 profile 并装好 fi 侧栏。此前用过 dsh 的话，登录与 API 凭据直接沿用。

pnpm start

09边界

它不假装
什么都能做。

下面每一条都能在 README 的「已知限制」里找到对应事实。

LIMIT 01

只有 macOS 是端到端

Finder 服务、深链、关窗保活都是 macOS 行为；Windows / Linux 尚未充分测试。

LIMIT 02

没有 dmg，也没有自动更新

从源码跑，升级靠 git pull + pnpm install；打包与更新在路线图上。

LIMIT 03

握手行是唯一契约

dsh 只打印一行登录 URL，没有 --print-url；格式变了要同步 URL_LINE_RE，否则起不来。

LIMIT 04

定时任务只在 fi 运行时调度

fi 没运行就不触发；错过的时间点下次启动静默顺延，不补跑。

LIMIT 05

侧栏依赖 dsh 内部槽位

dsh 大版本改动 slot / hook 面时，fi 侧栏会静默退回原生侧栏，不会报错给你。

LIMIT 06

关窗＝常驻后台

macOS 上 fi 不会自己退出，dsh 子进程与 cron 调度器跟着窗口一起常驻。
